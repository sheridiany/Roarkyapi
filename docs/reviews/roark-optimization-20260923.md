## 本次直接核实的现状

- 首页仅提供控制台、法律链接和厂商模型展示。邀请注册提示向管理员索取邀请码，同屏没有申请/联系入口。
- 首页代码 `web/src/features/home/components/provider-cards.tsx:33` 写死模型展示。线上展示 GPT Image 2、2.5 Flare、2.5 Sunburst；当前 status=1 的渠道模型列表没有这些模型。此结论是配置不匹配，并非收费调用验证。OpenAI 启用渠道当前登记的是 6 个 codex/ 文本模型。
- `web/src/features/home/components/gateway-models.tsx` 目前仅厂商/分组筛选，无搜索及能力筛选；首页展示名与可直接调用的模型 ID 来自不同来源。
- 标准充值 Price=1、配置汇率=7.3、钱包展示 USD；价格页按人民币标准充值成本展示。必须明确区分支付人民币、账户额度、官方美元参考价，不能混称实际美元资产。
- `web/src/features/home/lib/official-price-comparison.ts:33` 的官网参考价为本次上线的静态快照，已有日期和 Gemini 到期保护，但仍需后续核价流程。
- `web/src/features/usage-logs/components/user-usage-logs.tsx:350` 显示用量、缓存、总耗时/首字耗时、状态和费用，但 request_id 仅作行 key，没有可复制请求编号/完整错误详情入口。
- 数据库配置 RetryTimes=2；自动禁用/启用渠道选项未持久配置，当前代码默认 false。不能据此断言全站没有其他健康管理，但值得验证故障隔离策略。
- 最近 24 小时有 240 条消费日志、450 条错误日志；450 条对应 150 个不同请求 ID，全部集中在旧渠道 9 / gpt-6-astra，涉及一个用户，时间约 15:54–16:12。最近一小时为 2 条消费记录，无错误记录。样本少、重试会重复记录，不应计算成“全站 65% 失败”，也不能用最新两个请求承诺高可用。
- 本机小时归档有 48 份，最近一份约 33 分钟前。备份文档记录过隔离恢复演练，但明确尚未配置持续自动异地备份；本轮未全面审计所有外部备份系统。
- 单次桌面浏览首页，主 JS 解压约 1.96 MB，另一块约 0.72 MB，部分资源来自缓存。DOMContentLoaded 约 1.81 秒、load 约 2.42 秒，仅为此环境一次观察，不能当成 LCP、移动端或全国访问基准。现有动画已经处理 reduced-motion 和页面可见性，不应误报为完全没有降级。

## 用户确认的范围与个人账号生图

用户明确不需要接入向导，已从计划中移除。优先调查个人 GPT 与 Grok 账号的生图接入。

- 个人 GPT 已接入 Codex 渠道，但 `relay/channel/codex/adaptor.go` 的 `ConvertImageRequest` 明确返回 endpoint not supported；当前只能据此确认本站该适配器没有 Images 接口，不能推断账号没有生图权益。
- OpenAI 官方支持 Images API 和 Responses 的 image_generation 工具，但官方 API 的能力不能直接证明个人 ChatGPT OAuth 所用 `/backend-api/codex/responses` 支持同样请求。下一步须验证该路径的工具支持、图片结果提取及费用结算。
- 目前启用的 Grok 渠道指向两个第三方 API 上游，配置只有 grok-4.5/4.6/4.7 文本模型，尚未发现直接接入个人 Grok 账号的证据。需要确认个人 Grok 的接入位置，再验证生成和编辑接口。
- 历史 GPT 生图成功记录来自供应商 API 渠道，不能作为当前个人 GPT 渠道已打通的证据。本轮未发送收费生图请求。
- 验收应覆盖电脑与手机生成、图片编辑、图片下载、失败反馈和实际扣费；模型应在打通后同步到首页、定价和测试页，不能只登记名称就宣称可用。

依据：[OpenAI 图片生成](https://developers.openai.com/api/docs/guides/image-generation)、[xAI 图片生成](https://docs.x.ai/developers/model-capabilities/images/generation)。两者文档描述的是 API 能力，个人账号接入需要独立验证。

## 推荐顺序

| 顺序 | 工作 | 验收 | 相对成本 |
| --- | --- | --- | --- |
| 1 | 统一模型目录与可用渠道。不可用标“暂不可用”或移出可用清单；区分品牌展示名和复制调用 ID。 | 首页、定价、密钥/模型测试选择器与实际渠道一致，停用渠道不会留下可用承诺。 | 低至中 |
| 2 | 个人 GPT / Grok 生图接入验证与补齐。区分个人账号与供应商 API，确认实际可用协议后接入。 | 生成、编辑、下载、失败反馈和计费通过真实端到端验证；不以网页能生图代替中转接口验证。 | 待协议验证 |
| 3 | 使用日志故障详情＋请求级统计。提供请求编号、最终状态、费用状态、错误原因和下一步；内部重试另计。 | 150 个请求不会显示为 450 次客户失败；流中断与 HTTP 200 成功分开；不暴露上游密钥或管理员审计。 | 中 |
| 4 | 可靠性验证与恢复。按错误类型有界重试、冷却、同模型备用渠道，检查长请求流式传输和超时链。 | 首字前失败可按策略恢复；已输出的流不悄悄重放；换模型必须用户选择；请求有总时间预算。 | 中至高 |
| 5 | 计费解释闭环。统一支付/额度/人民币成本文案，增加请求估算、缓存/长上下文说明、充值到账状态。 | 用户能把价格页→充值→一条调用费用对上；未知官方价不编造；官网核价只通知，不自动改管理员费率。 | 中 |
| 6 | 模型搜索与能力筛选。写代码/普通对话/生图/长文本、接口协议、输入输出模态、可复制 ID。 | 推荐基于本站实测能力；未知能力标待验证；不拿价格分档阈值当上下文容量。 | 低至中 |
| 7 | 轻量状态及客服入口。按模型组展示最近可用性/首字延迟/事件，首页补价格、教程、申请邀请和联系支持。 | 样本不足明确提示；客户从注册受阻到联系支持有直接路径；保持现有品牌和首页构图。 | 低至中 |
| 8 | 自动异地备份和发布验收。加密备份到独立位置，保留对应二进制，定期隔离恢复；维护业务验收脚本。 | 模拟主机不可用仍能恢复；发布覆盖登录、密钥、文本流式/非流式、生图协议、查费用、旧页面继续使用。 | 中 |
| 9 | 首页加载专项。检查公共入口是否带入过多后台模块，按路由拆分、图标按需加载，实测移动端性能。 | 用真实用户 P75 LCP/INP/CLS 验收，不用 build 总文件大小代替首屏性能。 | 中 |
| 10 | 用量预警和预算体验。复用现有密钥额度/模型限制；先补低余额通知，再评估周期预算、并发限额。 | 设置在服务端生效、并发不会绕过预算；不会重复扣费或因失败重试错误计数。 | 中至高 |

第一批优先验证 2，再交付 1、3；同时安排 8 的异地备份。第二批 4、5、6、7；性能和预算按实际访问/调用量进一步排序。暂不建议新增复杂套餐、返佣、无人验证的自动跨模型切换，或为此更换整套网关。

## 外部依据与适用边界

- [OpenRouter Quickstart](https://openrouter.ai/docs/quickstart)：以明确的 Base URL、模型 ID、SDK 示例缩短首次调用路径。本站已有部分导入能力，建议补齐而非重建。
- [OpenRouter Models API](https://openrouter.ai/docs/api/api-reference/models/get-models)：提供模态、上下文、价格与 supported_parameters，可借鉴能力目录；厂商能力不能直接等同于本站渠道能力。
- [Cloudflare 请求处理](https://developers.cloudflare.com/ai-gateway/configuration/request-handling/) 和 [LiteLLM Router](https://docs.litellm.ai/docs/routing)：可配置超时、重试、回退/冷却。建议先完善现有重试，不盲目增加次数。
- [LiteLLM Endpoint Activity](https://docs.litellm.ai/docs/proxy/endpoint_activity)：将入口请求计数与花费记录分开，可避免内部重试重复计算客户失败。
- [New API 日志与异步任务](https://docs.newapi.ai/zh/docs/guide/feature-guide/user/log)：已有用量/耗时、首字信息及管理员重试链等能力，应复用底层数据，通过用户自己的使用日志提供可理解详情。
- [Cloudflare 524](https://developers.cloudflare.com/support/troubleshooting/http-status-codes/cloudflare-5xx-errors/error-524/) 当前说明默认 Proxy Read Timeout 为 125 秒。此前约 120 秒故障不能仅靠调长应用超时修复；需分别验证边缘代理、Nginx、上游和流式返回。长任务可评估任务状态轮询，不能假设任何文本/视频分析接口都原生支持异步。
- [Google Web Vitals](https://web.dev/articles/vitals)：以移动/桌面真实用户 P75 的 LCP ≤2.5s、INP ≤200ms、CLS ≤0.1 为体验目标。这是目标，不是本站已测得结果。

更完整的外部资料与成本边界见 [外部对照研究](gateway-market-research-20260923.md)。上述预计收益属于产品判断，需要用首次调用成功率、成功耗时、去重后的最终失败率、充值到账情况和客服问题类别验证。
